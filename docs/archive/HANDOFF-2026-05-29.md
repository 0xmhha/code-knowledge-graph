## §2. Evaluation DB 재생성

### 2.1 무엇이 필요한가

CKG eval은 **go-stablenet의 그래프 DB**가 사전 빌드되어 있어야 한다.
이전 머신의 `$EVAL_DB_ROOT` 디렉토리 (예: `~/Work/github/tools/go-stable-code`)
에는 다음 5개 DB가 존재했다:

```
graph.db                          # HEAD (가장 최신 commit) — 단일 파일
manifest.json                     # HEAD 의 manifest
graph.db-{shm,wal}                # SQLite WAL/SHM (자동 생성)
stablenet-0bf2f4d1bfeb/           # commit 0bf2f4d1bfeb 시점의 그래프
stablenet-319b84d113c5/           # commit 319b84d113c5 시점의 그래프
stablenet-940e9f281edb/           # commit 940e9f281edb 시점의 그래프
stablenet-98f05c2a0c16/           # commit 98f05c2a0c16 시점의 그래프
```

각 `stablenet-<short-sha>/` 디렉토리는 `--at-commit=<sha>`로 빌드된
시점-고정 그래프다 (CKG의 `cmd/ckg/build.go` worktree 모드).

> **새 머신에서는 이 5개를 다시 빌드해야 한다.** Makefile의
> `eval-build-dbs` 타겟이 이 정확한 절차를 캡슐화하고 있다.

### 2.2 LLM 프롬프트 템플릿

새 머신·새 세션에서 **첫 메시지로 그대로 복사해서 LLM에 전달하면**
DB를 재생성한다:

```text
# Eval DB 재생성 요청

CKG eval 환경을 새 머신에 부트스트랩 중이다. 다음 절차로 진행해줘.

## 사전 조건 확인
1. `go-stablenet` 저장소를 로컬에 클론. 위치 자유.
   예: `~/Work/github/stable-net/go-stablenet`
2. 이전 머신에서 사용했던 4개 commit SHA 확인:
   - 0bf2f4d1bfeb
   - 319b84d113c5
   - 940e9f281edb
   - 98f05c2a0c16
   이 SHA들이 클론한 go-stablenet 저장소에 존재하는지
   `git -C <stablenet-경로> cat-file -e <sha>^{commit}` 로 검증.

## 셋업
1. `.env.local` 파일을 CKG 저장소 루트에 생성:
   ```
   STABLENET_SRC = <go-stablenet 절대경로>
   EVAL_DB_ROOT  = <evaluation DB 저장 경로>
   ```
   (예전 머신: STABLENET_SRC=$HOME/Work/github/stable-net/go-stablenet-latest,
   EVAL_DB_ROOT=$HOME/Work/github/tools/go-stable-code)
2. `make build-no-viewer` 로 `bin/ckg` 빌드.

## DB 빌드
HEAD + 4개 commit 스냅샷을 한 번에 빌드:

```bash
make eval-build-dbs AT_COMMITS="0bf2f4d1bfeb 319b84d113c5 940e9f281edb 98f05c2a0c16"
```

각 빌드는 `--at-commit=<sha>` + `--out-tag=auto-commit-hash` 조합으로
`<EVAL_DB_ROOT>/stablenet-<short-sha>/` 디렉토리에 graph.db를 떨군다.
HEAD는 별도 `--at-commit` 없이 빌드되어 `<EVAL_DB_ROOT>/stablenet/`
또는 `stablenet-<HEAD-short-sha>/`로 떨어진다 (--out-tag 동작).

## 검증
빌드 후 모든 DB가 정상인지 확인:

```bash
for d in $EVAL_DB_ROOT/stablenet*; do
  echo "=== $d ==="
  ./bin/ckg report --graph=$d | head -10
done
```

각 DB는 `nodes`, `edges`, `pkg_tree_edges`, `topic_resolutions`
숫자를 출력해야 한다. 0이면 빌드 실패.

# 또는 CLI 백엔드 (claude + cliwrap-agent 필요)

결과는 `eval/results/stage-b/{results.csv,report.md}`에 떨어진다.
이 파일들은 gitignored (`.gitignore`의 `docs/STAGE-B-EVAL-RESULTS-*.md`
규칙 참조) — 커밋하지 말 것.

## 한계 / 주의

- `--at-commit`은 git worktree를 임시 디렉토리에 만들고 그 안에서
  파싱한다. go-stablenet 저장소가 작업 트리를 가지고 있어야 함
  (얕은 clone — shallow clone — 은 worktree add가 실패할 수 있음).
- 빌드 시간: HEAD 1회 + 4개 commit = 약 10-15분 (M1/M2 기준).
- 재실행 시 graph.db가 존재하면 skip. 강제 재빌드는 `FORCE=--force`.
```

### 2.3 Makefile 동작 요약

`make eval-build-dbs`의 핵심 절차 (Makefile L170-193):

1. `.env.local`에서 `STABLENET_SRC` / `EVAL_DB_ROOT` 로드
2. 둘 다 set 되어 있는지 + STABLENET_SRC 경로 존재 확인
3. HEAD 빌드: `ckg build --src=$STABLENET_SRC --out=$EVAL_DB_ROOT/stablenet
   --out-tag=auto-commit-hash --lang=go`
4. `AT_COMMITS=` 변수의 SHA마다 `--at-commit=$sha`로 동일 빌드
5. 결과 디렉토리 ls

`--out-tag=auto-commit-hash`는 source tree의 HEAD short SHA를
`--out`에 자동 append (예: `stablenet` → `stablenet-a5c8cb0`).

### 2.4 알려진 limitation

| 항목 | 영향 | 우회 |
|------|------|------|
| 빌드 캐시 키에 schema 버전 포함 | schema bump 시 자동 cold rebuild | 없음 (의도된 동작) |
| go-stablenet의 vendored deps | 빌드 시간↑, 노드 수↑ | `--files-from`로 include/exclude 패턴 지정 |
| `--at-commit`이 worktree 만들 때 디스크 사용 | tmp에 코드 사본 1개 | 다음 빌드 전 cleanup 자동 |
| 동시에 같은 outDir에 빌드 시도 | graph.db 충돌 | per-commit outDir로 자연스럽게 회피됨 |

### 2.5 cleanup / 재시작

문제 발생 시 처음부터:

```bash
# 1. DB 전체 삭제
rm -rf $EVAL_DB_ROOT/stablenet*

# 2. 재빌드
make eval-build-dbs AT_COMMITS="0bf2f4d1bfeb 319b84d113c5 940e9f281edb 98f05c2a0c16"
```

특정 commit만 다시:

```bash
rm -rf $EVAL_DB_ROOT/stablenet-0bf2f4d1bfeb
make eval-build-dbs AT_COMMITS="0bf2f4d1bfeb"
```
